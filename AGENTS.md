# Runner Dashboard: notes for agents

Rust work follows `.agents/skills/rust-practices` (also linked from `.claude/skills`). Repo
specifics that take precedence:

- **Verify loop** (the Solo "Tests" command runs all of it):
  `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo test --workspace`, `pnpm typecheck`, `pnpm test`. `cargo-nextest` isn't installed.
- **Toolchain:** rustc 1.93, edition 2024, `rustfmt.toml` width 120. Don't change the global
  toolchain.
- **Lints** live in `[workspace.lints]` in the root `Cargo.toml`. Integration tests and examples
  opt out of `unwrap_used` per file, with a reason.
- **TypeScript bindings** in `src/bindings` are generated by ts-rs when `cargo test -p fleet --lib`
  runs; commit them with the Rust change. Give exported names a prefix (`Fleet…`) when they could
  collide.
- **Demo fixture:** regenerate `src/fixtures/demo-fleet.json` when the views it covers change:
  `cargo run -q -p fleet --example demo_json > src/fixtures/demo-fleet.json`.
- **Error text** from `EngineError` and the desired-state operations is shown to the user as is,
  so it's written as sentences. That's deliberate, despite the lowercase-messages guideline.
- **Safety:** tests never contact a real host or the GitHub org; they fake GitHub, SSH and
  native services. Only reviewed plans change machines (apply, retire, decommission and restart
  from the machine and runner panes). Don't run any of them, or mint runner tokens, without the
  user asking. Read-only checks (`scripts/fleet-parity.sh`) are fine.
- **Terms** in UI text and docs: "machine" for a computer, "host" only for an inventory
  `[[hosts]]` entry. The doctor feature is "Runner checks"; `doctor` is its API and CLI name.
- **Runner Fleet parity:** `crates/fleet/src/desired` ports `soloterm/runner-fleet`. Keep its
  behaviour and messages unless a change is intended, and don't modify that repo.

## The runner fleet

The inventory and its format are described in [docs/FLEET.md](docs/FLEET.md).
`inventory/fleet.toml` is private and Git-ignored: never stage it, and keep real hostnames,
usernames and host-specific notes out of every other file. Tests use the fictional
`inventory/fleet.example.toml` and must build and run without the private file. These rules
carry over from Runner Fleet:

- Keep plan and apply separate. Read-only paths never mint tokens or change GitHub, hosts,
  services, directories or power settings.
- Never use `--replace`, move a configured runner directory, store a secret, or add broad or
  glob-based deletion. Retirement resolves and checks an exact inventory runner name and path,
  and keeps the workspace.
- Decommission needs `decommission = true` in the inventory first; apply never installs or
  starts a decommissioned runner.
- Apply checks the runner group policy (all private repositories, no public ones, all
  workflows) before registering, and every runner registers directly into that group with
  `--runnergroup`.
- A host migrating from legacy runners moves one runner at a time and keeps each legacy runner
  until its replacement is online, idle, configured and active.
- Native services only: per-user LaunchAgents on macOS, systemd on Linux, a Windows service or
  a logon task (`windows-logon`) on Windows. No containers, ARC, Ansible or VMs.
